# Consistent backups and recovery (#48)

These are privileged **operator commands**, not member-facing downloads. A backup includes the complete SQLite database (including private reviews, removed/revoked data, audit and sessions), uploaded native covers/avatars and a small runtime file containing timezone/language. The business export is a different format. Keep backups outside any web-served tree in storage restricted to the operator; on Windows configure the destination ACL, since POSIX mode bits do not establish a Windows ACL. Use an encrypted destination and a separately protected copy of deployment secrets/configuration. Archives themselves are not encrypted. Frequency, encrypted destination, off-device copy and scheduler setup remain deployment choices, not configured by this issue.

Inside `backend/`, with the intended deployment environment explicitly selected:

```powershell
uv run python manage.py backup_club --destination C:\private-bookclub-backups --keep 7
uv run python manage.py restore_club_backup --archive C:\private-bookclub-backups\<archive>.zip --destination C:\private-bookclub-recovery\<new-location>
```

`--keep` is required and accepts 1–30 snapshots. The example value is illustrative, not an agreed retention schedule. Point the deployment's existing scheduler at the backup command; exit status is nonzero on failure. Do not run these examples against the owner's development storage merely to verify them. Automated tests use fictional disposable SQLite/media directories only.

The command acquires SQLite `BEGIN IMMEDIATE` on a dedicated connection, takes the online backup through a **different read connection**, checks SQLite integrity and captures private uploads before releasing the write reservation. This includes committed WAL data and prevents database commits during the DB/media capture. Brief reads continue; concurrent writes can wait/fail under their usual timeout, so schedule at quiet times and keep this modest club's archives small. Media keys are immutable and application replacements/removals follow database commits; out-of-band filesystem mutation is unsupported. Missing referenced native uploads or unexpected/symlinked/junction filesystem entries fail the backup. No external media URL is fetched.

An archive contains `database.sqlite3`, `runtime.json`, native `media/avatars/<key>.webp` / `media/covers/<key>.webp`, and a versioned SHA-256/size manifest. The total uncompressed limit is 2 GiB. The ZIP is created in private temporary storage, synced and renamed into place only when complete. Rotation removes only directly contained, recognized archives with the controlled filename and valid format manifest. It preserves unrelated/unrecognized files and never deletes older backups when capture fails. If rotation itself fails, the new complete archive remains available and the command reports failure; fix destination access before the next scheduled run. Deleted club data can remain in older snapshots until those snapshots rotate out.

Restore refuses an existing destination, validates the closed member list, sizes, hashes and SQLite integrity, rejects duplicates/traversal/symlinks/encrypted entries, and writes only regular files. It cleans its own newly created files on an integrity failure. It does not replace a running database or switch a deployment automatically. Before an actual cutover, stop writers, verify the recovered records/media, restore the separately protected environment (OAuth/application secrets, HTTPS hosts/cookies and private media configuration), then explicitly select the recovered database/media paths. Timezone/language in `runtime.json` are reference values, not executable settings.

Tests cover committed WAL recovery, records/media/runtime equality, blocked writers with usable readers, lock release, bounded rotation, missing uploads/disk failure, invalid retention, archive traversal/extra/duplicate/symlink/hash rejection, and command-level fresh recovery/refused overwrite. Run `uv run pytest tests/integration/test_backups.py`; full backend/frontend CI is required before merge. Relevant sources: [SQLite online backup](https://www.sqlite.org/backup.html), [backup connection restrictions](https://www.sqlite.org/c3ref/backup_finish.html).
